// What it is

Big work doesn't fit in one chat.

A migration, a new product area, a rewrite. Agents can do the work, but the plan, the open decisions and the blockers end up scattered across sessions. MILOOPS keeps them in one mission you can see.

01 · Plan

A mission, not a prompt

A mission holds the destination, decisions so far, what's not yet specified and what's out of scope. Work is split into tickets, and each one knows what it's waiting on.

02 · Delegate

Agents take what's unblocked

Agents pick up tasks that are ready, one at a time, and write down what they did when they finish.

03 · Decide

You keep the calls that matter

Decision tickets ask you directly. An agent can't close one without your answer, and every answer lands in the mission's decisions.

// FAQ

Questions, answered.

Something missing? Open an issue on GitHub.

What is MILOOPS?

A command center for planning and finishing big projects with AI coding agents. It runs on your computer and shows every mission, task, agent and open question in one window.

Who is MILO?

MILO, the Mission Intelligence & Logistics Operator, is the voice of the command center. It reports status, relays agents' questions to you and briefs you on the mission. It never answers on your behalf.

Which agents does it work with?

Any AI coding agent that connects through MCP. Claude Code and Codex have first-class support: one command connects them and adds the /milo command to their chat.

Can I stay in my agent's chat?

Yes. /milo new frames an idea with you and turns it into a mission. /milo resume picks up the work, /milo status tells you where things stand, and /milo inbox lets you answer waiting questions right in the chat. The command center shows it all live.

Does my data leave my machine?

MILOOPS runs on your computer and keeps your plans in your project folder. If you connect GitHub or Linear, your computer talks to them directly, and your keys stay on your computer. Your agents still use their own AI services.

Do I need GitHub or Linear?

No. Plans are saved in your project by default, with no account. If your team already works in GitHub Issues or Linear, connect it in Settings: missions, tickets, decisions and comments sync both ways, and changes made there show up within seconds.

What happens if I go offline?

Work keeps going. Changes headed for GitHub or Linear wait in a queue and are sent in order as soon as the connection is back.

Can an agent make a decision for me?

No. A decision can't be closed until you've answered it. The agent drafts a summary, and you confirm it. Every decision lands in the Decisions log, which you can export.

How is spend tracked?

Each agent reports the tokens it uses and what they cost. You see both per agent and for the whole mission, always on screen.

Is it free?

Yes. MILOOPS is free and open source, and it runs on your computer.

Technical details
  • Install: npx miloops in your project folder runs the latest version without installing anything. To keep it installed, use npm i -g miloops, then miloops. Requires Node.js 20 or newer.
  • Demo: pick Demo in setup, or add ?tracker=demo to the command center address. The demo mission lives in memory and resets on reload; switch trackers in Settings.
  • Local server: starts on localhost:7420 (the next free port if that one is busy) and opens your browser. Flags: --port, --dir for the data folder, --no-open to skip the browser.
  • Agents: connect through MCP (Model Context Protocol). npx miloops connect claude registers the MCP server with Claude Code and adds .claude/commands/milo.md; npx miloops connect codex does the same for Codex (~/.codex/prompts/milo.md, plus a config.toml entry). Any other MCP client can run npx -y miloops mcp over stdio in your project.
  • Data: missions, tickets and decisions are markdown files in .miloops/ inside your project. Nothing is sent to MILOOPS servers.
  • GitHub and Linear: connect in Settings. GitHub reuses your gh login or GITHUB_TOKEN; Linear takes a personal API key. Keys are kept by the local server in ~/.config/miloops, never sent to the browser. Missions are labelled issues, tickets are sub-issues, and blocking uses native dependencies (GitHub) or "blocks" relations (Linear). Writes made offline or while rate limited queue and send in order.
